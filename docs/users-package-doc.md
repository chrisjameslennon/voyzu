# Users module documentation

**Module:** `@voyzu/users`

Manages user identity, roles, access mode and the user lifecycle.

## Install

```sh
npm install @voyzu/users
```

### SQL script

The installation creates the user enums and table. Shared domains such as `business_code`, `active_status` and `audit_timestamp` are supplied by the Voyzu platform. Passwords are stored as hashes and are never returned by the API.

[SQL source](../packages/@voyzu/auth/install/db/sql/app-user.sql).

```sql
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_type
    WHERE typname = 'user_role'
      AND typnamespace = current_schema()::regnamespace
  ) THEN
    CREATE TYPE user_role AS ENUM (
      'ADMIN',
      'STANDARD'
    );
  END IF;

  IF NOT EXISTS (
    SELECT 1 FROM pg_type
    WHERE typname = 'user_access_mode'
      AND typnamespace = current_schema()::regnamespace
  ) THEN
    CREATE TYPE user_access_mode AS ENUM (
      'UI',
      'API',
      'UI_AND_API'
    );
  END IF;
END $$;

CREATE TABLE IF NOT EXISTS app_user (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY (START WITH 10000),
    code business_code UNIQUE CHECK (length(code) <= 20),
    email TEXT UNIQUE,
    display_name display_name NOT NULL,
    password_hash TEXT NOT NULL,
    role user_role NOT NULL,
    access_mode user_access_mode NOT NULL DEFAULT 'UI',
    implementer_access BOOLEAN NOT NULL DEFAULT false,
    status active_status,

    creation_date audit_timestamp,
    creation_actor_type actor_type,
    creation_user_id TEXT,
    creation_mutation_id UUID,

    updated_date audit_timestamp,
    updated_actor_type actor_type,
    updated_user_id TEXT,
    updated_mutation_id UUID,

    deletion_date audit_timestamp,
    deletion_actor_type actor_type,
    deletion_user_id TEXT,
    deletion_mutation_id UUID,

    CONSTRAINT app_user_email_trim CHECK (email IS NULL OR email = btrim(email)),
    CONSTRAINT app_user_email_not_blank CHECK (email IS NULL OR length(email) > 0),
    CONSTRAINT app_user_implementer_access_admin_only CHECK (implementer_access = false OR role = 'ADMIN')
);
```

## HTTP API

Paths include the host's default `/api` prefix. Expand an operation for its request, response and example. DTO links describe the transport shapes; the semantic contract is linked above.

[Route definitions](../packages/@voyzu/auth/modules/users/http-api.routes.ts) and [handlers](../packages/@voyzu/auth/modules/users/server/http-api/user.http.handlers.ts).

Management operations require an authenticated admin. Profile operations apply to the authenticated user. Organization-access operations delegate assignments to the Organization module. The curl examples use a placeholder authentication cookie issued by the implementing authentication module.

## Seed data

Create the initial administrator when the user table is empty. Do not overwrite an existing user's credentials when installation is repeated.

| Field | Value |
| --- | --- |
| User code | `ADMIN` |
| Display name | Admin |
| Email | Not supplied |
| Initial password | `password` |
| Role | `ADMIN` |
| Access mode | `UI` |
| Implementer access | `true` |
| Status | `ACTIVE` |

The seed process hashes `password` using the password-hashing implementation before storing it in `password_hash`. The plaintext password is not persisted.

## Components

### User list view

Displays user accounts using the standard list pattern: filters, search, multi-selection and row navigation. Provides Add User, activate, deactivate and delete actions. Creation uses the standard modal and validation pattern.

[UserList component](../packages/@voyzu/auth/modules/users/client/UserList.tsx).

### User detail view

Displays user details using the standard detail pattern, with a status panel and Save at the top right of the form. Fields include code, display name, optional email, role, access mode and implementer access. Header actions include Back, Activate, Deactivate, Change Password and Delete.

The Organization Access tab integrates with the Organization module to select assigned organizations for STANDARD users. ADMIN users have access to all organizations. Organization assignments remain owned by the Organization module.

[UserDetail component](../packages/@voyzu/auth/modules/users/client/UserDetail.tsx) and [Organization Access tab](../packages/@voyzu/auth/modules/users/client/UserOrganizationAccessTab.tsx).
