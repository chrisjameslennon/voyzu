# Users package documentation

**Package:** `@voyzu/users`

## Implements Semantic Contracts

### @core/user

Owns system user identity and lifecycle.

#### Data definition

```ts
export type UserStatus = "ACTIVE" | "INACTIVE";

export interface User {
  id: number;
  code: string;
  email: string;
  displayName: string;
  role: string;
  status: UserStatus;
}

export interface UserContract {
  identifier: "id";
  dataDefinition: User;
  methods: UserMethods;
}
```

#### Methods

```ts
export interface UserListParameters {
  status?: UserStatus;
}

export interface UserMethods {
  get(parameters: {
    id: number;
  }): Promise<User | null>;

  findByEmail(parameters: {
    email: string;
  }): Promise<User | null>;

  list(parameters?: UserListParameters): Promise<User[]>;

  batchGet(parameters: {
    ids: number[];
  }): Promise<User[]>;

  create(parameters: {
    email: string;
    displayName: string;
    role: string;
  }): Promise<User>;

  update(parameters: {
    id: number;
    changes: Partial<Pick<User, "email" | "displayName" | "role">>;
  }): Promise<User>;

  activate(parameters: {
    id: number;
  }): Promise<User>;

  deactivate(parameters: {
    id: number;
  }): Promise<User>;
}
```

Users has no dependency on Authentication or Organization.

```text
@voyzu/users
      ▲
      │ dependsOn
@voyzu/authentication

@voyzu/organization
      │
      └── references User for organization access
```

## Persistence

The Users package owns the User table and all user persistence.

```sql
CREATE TABLE app_user (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    code TEXT NOT NULL UNIQUE,
    email TEXT NOT NULL UNIQUE,
    display_name TEXT NOT NULL,
    role TEXT NOT NULL,
    status TEXT NOT NULL
);
```

Authentication credentials and sessions are owned by `@voyzu/authentication`.

## HTTP API

Paths below are declared relative to the host HTTP API prefix.

| Method | Path | Request / Response | Result |
| --- | --- | --- | --- |
| GET | `/users` | ↑&nbsp;[UserListRequestDto](#userlistrequestdto)<br>↓&nbsp;[UserResponseDto[]](#userresponsedto) | Lists users, optionally filtered by status. |
| GET | `/users/[id]` | ↓&nbsp;[UserResponseDto](#userresponsedto) | Gets one user; 404 if absent. |
| GET | `/users/by-email/[email]` | ↓&nbsp;[UserResponseDto](#userresponsedto) | Gets one user by email; 404 if absent. |
| POST | `/users/batch/get` | ↑&nbsp;[UserBatchGetRequestDto](#userbatchgetrequestdto)<br>↓&nbsp;[UserResponseDto[]](#userresponsedto) | Gets multiple users; missing IDs are omitted. |
| POST | `/users` | ↑&nbsp;[UserCreateRequestDto](#usercreaterequestdto)<br>↓&nbsp;[UserResponseDto](#userresponsedto) | Creates a user. |
| PATCH | `/users/[id]` | ↑&nbsp;[UserUpdateRequestDto](#userupdaterequestdto)<br>↓&nbsp;[UserResponseDto](#userresponsedto) | Updates a user. |
| POST | `/users/[id]/activate` | ↓&nbsp;[UserResponseDto](#userresponsedto) | Activates a user. |
| POST | `/users/[id]/deactivate` | ↓&nbsp;[UserResponseDto](#userresponsedto) | Deactivates a user. |

## Types

DTOs reuse semantic contract types directly where their shapes match.

### UserListRequestDto

```ts
import type { UserListParameters } from "@voyzu/semantic-contracts/user";

export type UserListRequestDto = UserListParameters;
```

### UserBatchGetRequestDto

```ts
import type { UserMethods } from "@voyzu/semantic-contracts/user";

export type UserBatchGetRequestDto =
  Parameters<UserMethods["batchGet"]>[0];
```

## UI

The Users capability does not need to own its administrative screens.

The ERP UI may provide the Users list/detail screens and role/access configuration. Organization-specific user access remains owned by the Organization capability.
